## 已实现

1. 全屏预览左右滑动和上一张/下一张按钮，跨页边界保持预览打开。每次切图重置缩放、平移和参数面板。仅未放大的单指水平滑动切图；双指、放大拖动、参数面板和工具按钮不误切。它是原生缩放视图加单图切换，不宣称完整 iOS 连续跟手动画复刻。
2. 选择以会话内照片 ID 独立保存，不依赖当前页或缩略图文件。翻页、返回和预览勾选不丢失选择；全选仍明确为“全选本页”。单批最多 100 个不同 ID，保存串行执行，原生相册回调成功才记为已保存并取消勾选，失败项保留重试。退出/换连接清空选择，不声称进程死亡恢复。
3. 放大至约 1.4 倍触发完整原图请求，复用已有加密传输、SHA256 校验和 16 MiB 上限，不回退明文或把预览冒充原图。原图临时文件仅用于显示，不自动写入相册；保留预览底层直到原图 image-load 成功，避免解码时空白。切图/关闭移除高清文件，迟到字节清零、迟到写入清理，旧图 load/error 回调不能影响新图。保留最多 36 个缩略图文件，避免跨页缓存无限增长。
4. 同一连接新增经过认证的 `refresh` 指令，仅下载 profile 可用。复查现有 scanner 的 canonical 数据库；不新增扫描器、索引或数据库写入。快照验证成功后原子替换；失败保留旧快照。照片 ID 由随机会话私有盐和源身份生成不透明 HMAC，同一会话未变化照片刷新后 ID 不变，不把路径/UID/hash 当列表 ID 暴露。

刷新入口包括按钮和下拉。前台最新页空闲时每 30 秒检查一次，最多 18 次自动检查；选择、预览、保存、参数/原图读取、连接面板和旧页浏览时自动延后，不打断用户操作或悄悄重排正在查看的照片。服务器对快照重建最低 5 秒节流。新照片必须先由既有 scanner 入库，刷新不是重新冷扫。EXE 微信照片计数也随刷新更新。

## 复查修复

- 独立调试入口先前在建立快照后关闭只读数据库；新 refresh 会失败。改为由 source 持有到 server.stop，且只关闭它自己开的连接；EXE 共用数据库不会被关闭。合成真实 SQLite 测试验证新增索引记录在同一 source 出现。
- 256 请求额度耗尽时，旧 client 仅抛异常，可能让页面一直“载入中”。新增额度测试得到 RED 后补失败关闭通知；list/preview 同步异常也有页面收尾和新浏览码提示。
- 高清切图/原生 image 迟到回调、刷新期间后台退出、跨页缓存上限、旧 profile 权限和刷新失败保留旧列表均有回归。

没有修改 Live、NUAN5 resolver、Android 业务、安全配对协议、Windows 单实例生命周期或游戏文件。未删除现有 SQLite；用户已有 `tools/sample-analyzer/analyze.mjs` 修改未触碰。
