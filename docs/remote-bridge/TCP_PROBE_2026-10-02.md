# 局域网 TCP 连通性诊断（不是安全照片传输）

分支：`feature/remote-bridge-foundation`。用户要求继续小程序，并约束不付费；本轮明确允许推进独立局域网 TCP 合成测试。

## 依据与边界

用户贴出的微信官方网络说明：基础库 2.18.0 起提供 `wx.createTCPSocket`，允许同一局域网非本机 IP 和配置的服务器域名。此前 HTTPS 实机返回 `ERR_CERT_AUTHORITY_INVALID`，只证明自签名 HTTPS 在该手机被拒绝，不证明 TCP 或其他安全传输已经可用。

公开官方网络页面的浏览器读取被安全策略拒绝，没有绕过。当前 TCP 回调签名与字节类型仍须微信开发工具编译和真实运行确认；Node 模拟测试不能替代官方平台/真机验收。

本轮不申请证书/域名、不创建云环境、不购买、不发布，不变更现有 HTTPS、原生配对安全协议、SQLite 或其他模块。独立 TCP 测试是明文公开合成字符串，不支持媒体、凭据、UID、图库命令；不是 HTTPS 出错后自动降级，更不是生产传输协议。

## 实现

- 小程序专用页面 `pages/tcp-diagnostics/index`，首页新增独立入口。
- 专用测试 QR：`NikkiSyncLanTcpProbe` v1，仅私有 IPv4、有效端口、随机公开 nonce、最多十分钟有效期；拒绝额外字段（包括 token）与生产照片 QR。
- 请求 `NS-TCP-PROBE/1 <nonce>\n`，只接受 `NS-TCP-OK/1 <nonce>\n`；ASCII 有界 512 字节、分包拼接、5 秒超时、无自动重试。公开 challenge 匹配不是身份验证。
- 页面隐藏/卸载关闭连接、屏蔽迟到回调；扫码导致前后台切换时等待回前台再开始。
- 独立 `tools/wechat-tcp-server.mjs` 不导入图库/DB/resolver，严格选择唯一可识别私有 Wi-Fi 地址，随机端口、最多16活动连接、每连接5秒超时、十分钟停止。没有0.0.0.0、隧道或防火墙调整。无请求内容日志；QR只在忽略的 out 目录。

## 验证事实

1. 默认 Node test 隔离模式最初因沙箱 spawn EPERM 没有运行测试；不计入 TDD RED。
2. 改用现有项目的 `--test-isolation=none`，新增6项因缺失 production 模块失败，是真实 RED。
3. 实现后发现过期拒绝连接的清理问题，修复后新增 TCP 客户端5项及真实 Node 回环 TCP 1项通过；随后补页面生命周期测试，共7项。
4. 全部小程序相关 Node 测试（六个 test 文件）：25/25 PASS。首次完整运行曾因旧配置测试固定只有2个页面而23/24，更新页面合同后25/25。
5. `npm test -- --runInBand`：87/87 PASS，包含TypeScript build。

仅Node本机回环TCP与模拟wx/Page；尚未生成本轮微信预览、启动局域网监听或获得微信Android/iPhone TCP结果。未打包EXE/APK，未上传真实照片或手机截图。
