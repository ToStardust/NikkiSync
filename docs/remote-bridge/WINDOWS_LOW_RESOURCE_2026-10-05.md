# Windows 常驻后台低资源优化

日期：2026-10-05。用户要求降低后台常驻占用；本轮直接实现、回归、打包和采样。保留既有暖暖粉 UI、Android / 小程序功能及 Live 导出行为。

## 交付

使用 `release/NikkiSync-LowResource/NikkiSync-PC.exe`；后台及其资源仍放在 `runtime/`，根目录只有一个 EXE。保留整个发布目录，先从托盘退出旧版再打开新版，避免单实例机制激活旧版。未覆盖旧 PinkUI-Clean 包，未替换用户现有进程、正式数据库或开机启动项。

## 已实现

- `DesktopStatusService` 改用 `AssetRepository.count()` 的 SQL `COUNT(*)`，刷新状态不再加载整个素材表。只读聚合发现当前 224 个素材的 `metadata_json` 合计 11,642,871 字节（约 11.1 MiB）；旧版每两秒为显示一个数量读取这些参数。计数保留现有全部索引素材语义，实时反映新增和物理删除，显式传入 0 仍有效。
- 本地同步服务没有 WebSocket 订阅者时关闭 250 ms 的日志轮询。首个订阅者收到当前 revision 的 hello 并恢复轮询；最后一个离开时停止。历史变更继续通过已有 `/changes` 接口读取。
- 桌面隐藏时停止状态请求，恢复显示后立即刷新。WPF 隐藏 / 最小化时使用 WebView2 `TrySuspendAsync`，恢复时 `Resume`；防止异步暂停晚于恢复完成、把已显示的窗口留在暂停状态。后台配对与文件监听继续运行。
- 扫描请求合并相同和父子目录，串行执行。20 次同时请求同一目录只执行一遍；执行中来的事件排入下一遍。停止时等待扫描结束，且关闭所有根目录的原生 watcher，避免句柄遗漏和数据库关闭后写入。
- JPEG 参数尾部窗口由固定最高 2 MiB 改成从 64 KiB 开始、必要时逐级扩大，保留原 2 MiB 上限、V2 边界、原生 token 和 MD5 语义。大参数不截断，使用后清零临时缓冲。
- 元数据解析用库 revision、provider/version 和失败重试期限判断是否有新工作。没有变化时只读一个 revision，不重复加载和反序列化参数；到期重试及输入 / provider 变化仍有效。
- Bun 数据库连接缓存最多 64 条编译 SQL，采用 LRU；缓存语句，不缓存结果。参数重新绑定，新增行立即可读；淘汰不使调用方仍持有的语句失效。Node SQLite 路径保持原实现。
- 固定的微信协议模块编译为独立词法工厂，移除后台生成运行时中的多 VM 上下文。用户开启连接时才初始化模块，结束连接时清除模块导出缓存；不执行用户输入的代码，不更改手机协议及加密 / 文件大小限制。
- 后台 EXE 编译启用 Bun `--smol`。扫描、解析、微信请求（包括失败）、结束连接等工作完成后，在连续 5 秒没有新完成任务时合并执行一次 `Bun.gc(true)`。没有常驻强制 GC 轮询；退出时取消。Live 使用的 FFmpeg 仍按需启动。

内存回收是释放不可达对象，并非隐藏工作集数字或施加会中断 Live 导出的进程硬限额。

## 回归证据

先增加失败用例，再实现行为。RED 覆盖无订阅仍查日志、20 次并发扫描、停止扫描 / 多根 watcher、固定大尾部缓冲、无变化仍加载参数、隐藏 UI 请求、后台编译参数、微信工厂 / 缓存释放及失败请求回收。新增状态计数测试在旧实现明确报 `Status must not hydrate the library`，修改后通过。

- `npm run test:performance`：45/45 Node PASS，1/1 Bun PASS。重试测试使用 Node 可控 Date，避免机器繁忙时真实几十毫秒等待失真。
- `npm test` 的构建和核心回归：107/107 PASS。最后一次在 `test:performance` 已构建后执行相同核心测试命令，避免重复构建。
- `test:wechat` 的完整测试入口：174/174 PASS，包含真实本地 TCP、超过普通照片上限的 Live 传输、完整视频 / 音频包及既有导出校验。在已构建产物上执行测试入口，未重复构建。随后仅修改桌面状态计数；该变更由核心、性能及编译 EXE 验收覆盖。
- Windows 桌面壳：13/13 PASS。包括隐藏 / 恢复、暂停晚完成及退出取消逻辑。
- 最终 Bun 编译、.NET publish、单入口目录校验 PASS；`git diff --check` PASS。NuGet 漏洞信息查询仍有 NU1900 网络警告，不代表依赖安全审计通过。

## 编译 EXE 的资源采样

`tools/wechat-gallery/accept-desktop-exe.mjs` 创建私密临时数据库副本，正式库只读；测试副本关闭在线解析和远程字典，测试进程使用独立端口。游戏媒体只读，没有上传、设备相册写入或私人二维码 / key 输出。只结束本次测试的子进程，校验临时目录边界后清理副本。

最终 EXE 实际扫描 224 个素材，验证 Android / 微信入口、图库 224 项、生成 / 更新 / 结束连接、品牌图字节一致。以下均为后台单进程：先开启、更新并结束微信连接，预热 10 秒；无手机连接，每两秒请求一次桌面状态。12 逻辑处理器，CPU 为进程累计 CPU 时间差除以实际时间和逻辑处理器数。

| 指标 | 旧 PinkUI-Clean | 新 LowResource |
| --- | --- | --- |
| 实际采样时间 | 126.88 秒 | 124.06 秒 |
| 整机口径平均 CPU | 0.142% | 0.023% |
| 五次实际驻留内存 MiB | 138.5 / 137.9 / 137.9 / 138.3 / 137.9 | 115.6 / 114.9 / 115.0 / 114.6 / 113.6 |
| 首尾驻留内存变化 | -0.6 MiB | -2.0 MiB |
| 私有提交内存 MiB（不是实际驻留 RAM） | 320.7 / 320.9 / 314.6 / 317.3 / 311.0 | 295.1 / 296.2 / 291.8 / 286.0 / 282.8 |

原始报告：`out/idle-NikkiSync-PinkUI-Clean-120s-ui.json`、`out/idle-NikkiSync-LowResource-120s-ui.json`。新报告为最终后台哈希对应的重测，不使用此前候选版本的结果。

另外补测无桌面状态请求的后台场景：实际 21.83 秒，整机口径平均 CPU 0.006%，五次驻留内存为 109.8 / 108.9 / 108.3 / 108.3 / 108.3 MiB，首尾 -1.5 MiB；160 MiB / 增长 8 MiB 门槛同样 PASS。报告 `out/idle-NikkiSync-LowResource.json`。这是移除桌面请求后的后台采样，不是实际原生窗口托盘暂停验收。

验收脚本支持 `--idle-budget-mib=160`：五次驻留内存不超过 160 MiB，首尾增长不超过 8 MiB，否则保存报告并退出失败。最终两分钟测试 PASS。这是当前参考场景的回归门槛，不是运行时硬限额，也不保证所有机器 / 素材规模均为这个数值。

初次最终包采样因 WMI 查询 10 秒超时失败，未将其记为通过。采样器改用直接进程计数器，不依赖 WMI；旧参考报告的驻留内存和 CPU 同样来自进程计数器。当前不再额外读取私有驻留内存。

此前用户旧进程曾观察到约 1.8 GiB 驻留内存，同时微信连接未开启。该现象没有同样的运行时长 / 工作负载及堆记录，不能证明单一根因或拿它与新启动的 115 MiB 进程宣称 90% 以上降幅。整库状态刷新是本轮确认去除的重复分配路径。

### 验证边界

没有测量完整 WPF / WebView2 子进程合计内存，没有实际点击托盘验证原生 WebView 是否成功暂停；暂停 / 恢复仅通过逻辑测试和源码接线检查。以上采样不包含长时间手机传输、在线解析、Live 转码峰值或整日常驻，不能以两分钟无增长推断已完成整日稳定性验收。此轮没有新的手机实机验收、上传微信预览或发布。
