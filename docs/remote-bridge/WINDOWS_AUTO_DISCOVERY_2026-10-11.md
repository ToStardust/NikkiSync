# Windows 自动检测与清空默认设置验收｜2026-10-11

## 用户反馈与这次修复

测试用户在游戏开启、重开游戏、游戏关闭三种情况下都遇到 `GAME_NOT_FOUND`，手动选择文件夹也没有解决。用户要求首次启动优先自动查找，不依赖游戏正在运行；手动选择只能作为备选；先清空开发电脑的目录默认设置，实际测试通过后再提供新版。

上一版只沿目录向上验证 `InfinityNikki.exe + X6Game`，不会检查所选启动器目录下的游戏。它使用扩展名判断文件，也会误判带版本号的文件夹；有效旧缓存还会抢先于本次手动选择。这些问题已用失败测试复现。本机另发现启动器的卸载记录已经失效，桌面游戏快捷方式仍有效。测试用户的具体安装结构尚未取得，不能声称已经在对方电脑确认全部原因。

## 新流程

1. 本次明确手动选择优先。可选择启动器、游戏根目录或 X6Game/下级目录；验证真实文件类型，不按目录名有无点号判断。
2. 普通启动先验证已记住的位置；无缓存或原位置失效时，使用本机线索自动重新查找。
3. 自动线索包括程序所在位置、Windows 卸载安装记录、Epic 本地安装清单、桌面/开始菜单游戏快捷方式、各固定磁盘常见安装位置。所有候选均以真实游戏结构验证，不仅凭名称认定。
4. 运行中的游戏进程仅为最后的补充线索，同时识别 InfinityNikki 和 X6Game shipping 进程。首次启动无需开游戏。
5. 自动检测失败后，先提供“重新自动检测”，再提供“备选：手动选择安装文件夹”。重新自动检测清除此次窗口内的手动选择。
6. 成功时保存实际游戏根目录。日志 `game-discovery.log` 只含来源、数量、耗时和搜索边界；无个人路径、照片、参数、账户或密钥。

识别兼容根目录启动 EXE 和 `X6Game/Binaries/Win64/X6Game-Win64-Shipping.exe` / `X6Game.exe`。保留原始 GamePlayPhotos 优先级及尚未拍照安装的零目录扫描修复。

## 资源与边界

- 无缓存时只运行一次 Windows 只读探针，超时 8 秒；快捷方式检查最多 512 个，最多 128 个目录、深度 4。不会执行快捷方式目标或卸载命令。
- 文件夹补充查找限制深度、候选数量和时间，跳过游戏资源包、Saved/照片视频、Windows/Users/AppData、构建与缓存子树，不递归全盘读取文件。
- 缓存有效时直接验证，不再启动上述 Windows 探针或后台轮询。实际第二次检测只验证 1 个目录，耗时 7ms。
- 搜索范围有边界。极特殊目录且没有有效安装记录/快捷方式时仍可能需要手动选择；这也是保留备选入口的原因。
- 游戏文件保持只读。首次全相册索引仍需时间，继续使用现有启动进度界面。

## 真实单 EXE 验收

脚本：`tools/windows-performance/verify-game-autodiscovery.mjs`。

证据：`out/game-autodiscovery-rp4LLL/report.json`、`startup-screen.png`。这些本地报告不随发布包分发。

验收不是之前仅用空游戏标记文件的合成启动测试：此次真实游戏始终关闭，EXE、.NET 缓存、运行文件、WebView 和测试数据库全部放在系统临时目录，位于游戏安装树之外。自动启动没有注入正确游戏位置，也没有复制开发电脑的目录缓存。测试用全新数据库，实际扫描本机游戏照片；在线参数/字典服务关闭。

按用户要求，先将本机真实 `game-install-root.txt` 备份到忽略的 out 目录，校验备份 SHA-256 后清除这个默认文件。其余用户文件（包括数据库、配对等）在测试前后逐个比较 SHA-256，均保持不变。成功后，真实默认文件仅重新填入独立自动检测出的游戏根目录，供后续正常启动复用；没有清除配对或照片。
