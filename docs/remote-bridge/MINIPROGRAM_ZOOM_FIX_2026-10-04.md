# 小程序图片缩放反馈与切图事件隔离修复

日期：2026-10-04（Asia/Hong_Kong）。工作区 NikkiSync-RemoteBridge，分支 feature/remote-bridge-foundation。只修改小程序预览手势及相关回归测试；源码仍在本地，未提交、推送或合并。

## 用户反馈与代码诊断

用户实测双指缩放时照片不规则放大缩小，切换照片后仍持续。代码存在 `bindscale → setData(viewerScale) → scale-value` 的反馈链，并且旧原生组件的 scale/touch 事件未隔离。这是本轮已确认的代码缺陷，符合反馈现象；不是通过手机采样定位出的唯一运行时原因。

## 修复

- 实时缩放只记录私有 `_nativeScale`，不再通过 setData 回写 scale-value。每个新照片组件使用不可变 initialScale=1 初值。
- 每次打开或切换照片生成新的 frame key；原生缩放及触摸事件必须携带当前 frame，缺失或旧 frame 均忽略。重新打开同一照片也不复用旧 frame。
- 切图、关闭、后台及退出重置或失效当前手势状态，旧事件不能影响下一张，也不能触发下一张的高清下载。
- 未放大才允许滑动切图；双指、放大拖动不误切。高清图加载与工具栏更新不重建缩放初值，保留原有校验、迟到回调清理和流量限制。
