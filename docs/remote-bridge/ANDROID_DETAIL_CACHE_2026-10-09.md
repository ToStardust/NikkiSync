# Android 照片详情持久缓存｜2026-10-09

用户反馈重启手机 App 后查看照片又要读取穿搭和参数，要求手机保留缓存，同一穿搭减少重复读取。本次范围是 Android App；保留现有液态玻璃、GPU 渐进顶部模糊、粉色背景、预览手势、LIVE 与分享图新排版。

## 原因与行为

- 旧版 ImageLoader 已有磁盘缩略图缓存，但普通照片的 client.asset() 总是 GET 电脑。SavedMetadataSnapshotStore 供已保存照片页离线恢复使用（普通预览也会写入），普通图库没有复用它，且它不能代替完整资源/参数详情缓存。
- 新增私有 SQLite `nikkisync-detail-cache.db` 和 CachedAssetDetails，接入 MainActivity 建立的公共 NikkiSyncClient。预览、分享、普通保存和各 LIVE 导出路径均通过同一个详情读取入口。
- 只缓存实际读取的照片。图库分页/搜索不会预取全库详情，也不为未打开照片创建记录。已经读取、且版本未变的照片再次查看或重启 App 后不发详情 GET；图库列表仍需连接电脑同步，本次没有提供整个远端图库的离线主页。
- 缓存保留照片资源清单、motion 配对/时间戳及规范化 metadata。存储前移除 raw.nativeParam* 原始解析令牌/负载字段，保留字典版本与显示字段。认证私钥/配对凭证不进入详情缓存。
- namespace 使用 serverId + TLS 指纹，IP/端口变化可复用，其他电脑或 TLS 身份变化隔离。
- 分页、套装/散件搜索及 changes 的照片 revision 更新仅使相关缓存失效；PATCH 返回直接更新缓存。fullResyncRequired 清理本电脑缓存。版本没有时间型 TTL，避免每次启动因过期重复读取。
- 同一客户端的同照片请求通过 32 个固定锁合并；数据库 revision 标记拒绝迟到的旧版本写入。缓存世代由共享存储管理，清理/全量重同步后，旧连接的迟到请求也不能重新写入旧内容。磁盘缓存不可用时本连接退回网络读取。
- 不按“整套衣服相同”复用另一张照片的完整详情：焦距、滤镜、曝光、资源与 LIVE 配对属于各自照片。

## 部件与空间

- UI 部件图标改为电脑身份 + clothingId + dictionary.providerVersion 的磁盘/内存键。字典版本已知时跨照片共用；未知版本仍按照片隔离。分享图的图标键也采用该规则，版本从已有详情缓存读取，不为每个图标再请求照片详情。
- 图标并发读写使用独立临时文件、完成后原子发布。UI 同键下载去重，较旧未完成临时文件按 24 小时清理。缩略图磁盘空间按新增字节计数，只在需要时扫描/淘汰，不增加后台计时任务。
- 详情内容预算 32 MiB / 最多 5000 条记录，单条最多 1 MiB；超过时淘汰较早使用的记录。这里指响应内容预算，SQLite 文件/WAL/索引另有少量开销；删除后文件页可复用，不宣称物理文件立刻缩小。
- 原有 UI 缩略图预算 256 MiB、分享图图标预算 32 MiB 保留。这些是磁盘空间，并不全量装入 RAM。Saved 照片/离线快照与系统相册文件属于用户资料，不随详情缓存淘汰。
- “我的 → 本地缓存 → 清理照片详情缓存”只清理当前电脑的可重读详情，不删除照片或配对。接下来查看时重新读取。
