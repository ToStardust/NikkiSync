# Live 图设备验收记录模板

每个型号 + 地区 + 系统 + 相册版本独立建立记录；未填项一律“未验证”，禁止默认通过。测试范围仅 Live 图及其旋转。

## 环境身份

| 字段 | 必须记录 |
|---|---|
| Git SHA / APK SHA-256 | 实际参与测试的提交和构建产物，不使用旧 APK |
| 品牌 / 型号 / 地区版 | 精确 Build 信息与销售地区；不记录设备唯一标识 |
| 系统版本 / Android API | 完整版本，不只写 HyperOS / ColorOS / One UI |
| 相册包名 / versionName / versionCode | 自带相册和 Google Photos 分开 |
| profile ID | 包含自动或手动选择方式 |
| 样本 ID / SHA-256 | 仅获授权的非敏感图片和视频；注明帧率、尺寸、音轨、时长 |
| 源方向 / 封面 PTS 来源 | 原 EXIF / video rotation，canonical 或 sample_match_v1 |

## 自动旋转设备测试

先从仓库根运行 `python tools/livephoto/generate-fixtures.py`（Python + Pillow + ffmpeg），再从 `apps/mobile` 运行：

```sh
./gradlew testDebugUnitTest assembleDebug assembleDebugAndroidTest
./gradlew connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=app.nikkisync.mobile.media.live.LivePhotoRotationInstrumentedTest
```

Windows 使用 `gradlew.bat`。设备测试会安装测试 APK，必须由用户授权所连接的目标设备。工具没有设备时报告“未执行”，不能跳过后标绿。

两个测试分别覆盖原方向 0 和源 JPEG EXIF90 + 视频方向90；每个测试再跑 0/90/180/270 用户角度。非零输出检验真实像素四角色块、视频 rotation=0、物理尺寸、24帧/1秒与音轨存在，以及源文件不被修改。它不代替下面的 OEM Gallery 验收，也不直接证明音视频同步听感正确。

## 故障与批量回归

- 多选横/竖/普通/Live 混合：只修改被长按查看的那一张角度；正常点击仍用于勾选。若旧分支的交互实现本身不同，记录为继承问题，不扩大本任务重写整套图库。
- 两张 Live 分别90/270，确认批量输出互不共享角度；普通照片原有导出路径不变。
- 某张失败：保留其勾选和角度，不说该 Live 保存成功；已成功项也不能误清用户在运行期间新设的角度。
- 空间不足、下载中断、第二 URI insert 失败、写入失败、publish 失败：只补偿本次新建资源；绝不删除用户原媒体。
- vivo 只删除视频：显示 LIVE 不完整，静态图仍可打开；旧记录无 companion URI 显示待核验，不凭文件名猜关联。
- 应用进程被杀在插入/写入/发布之间：当前缺持久事务恢复，这项不得标通过；交给 Codex 增加 journal 后重测。
- 旋转时退出/取消：编码器确认停下后才清理临时资源；不能停止时保留私有临时目录并提供后续清理策略。
- HDR、HEIF、大图或不支持的编码器：明确错误，不降为静态、短视频或低分辨率后假称成功。

通过必须附日志/录屏或可审计的手测结果；不上传原私人照片或设备凭据。
