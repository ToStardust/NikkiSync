大喵相机助手：连接信息诊断

电脑上这样操作：
1. 先把本压缩包完整解压到桌面的一个文件夹，不要在压缩包预览里直接运行。
2. 打开电脑版大喵相机助手，保留正在连接/配对失败的状态。
3. 双击 Run_Connection_Diagnostics.cmd，等待显示 Report saved。不要点击 ps1 文件。
4. 把同一文件夹中新生成的 ConnectionReport-日期时间.txt 发回来即可。

手机上再补一张图（正在连接普通 Wi-Fi 时）：
打开设置 → Wi-Fi → 点当前已连接的网络 → 网络详情。
截图中能看到 IP 地址即可，各手机品牌的具体入口名称可能略有不同。
如果这一页有密码或分享二维码，请避开这些内容。
如果是运行 App 的手机自己开热点，直接说明“本机开热点”，无需寻找 Wi-Fi 地址。

报告会记录：助手版本、配对地址、电脑 IPv4/子网掩码/网关、网卡类型、同步端口监听与电脑本机访问情况。
第二版还会只读检查 Windows 防火墙当前网络类型、是否启用、阻止所有入站状态，以及当前监听程序/同步端口相关规则的数量。
第三版会将“公用/专用”网络类型对应到具体网卡，并把当前后台规则的地址范围、接口限制、服务限制概括为固定类别。用于判断是否有“添加了允许规则但仍被另一条阻止规则拦截”的情况；读取不到时显示 Unknown。
只显示 Any、LocalSubnet、Restricted 等类别，不输出规则中其他设备的地址、服务名、接口标识或规则名称。
第四版补充“一条冲突、零条可自动处理”的跳过原因，以及本地规则修改策略；不更改规则，也不把候选项当作已修复。
第五版与新版助手一致，使用完整规则特征区分同名 TCP/UDP 或其他程序规则；只有仍无法区分的身份才标记 AmbiguousRuleIdentity。电脑版二维码页面也可直接导出诊断 ZIP，无需单独下载此脚本工具。
常见原因：ProtocolNotTcp（规则限制所有协议，不能作为单独 TCP 规则修改）、GroupedRule（规则属于分组）、SecurityRestriction（附带安全条件）、UnreadableRepairFields（部分必要字段无法读取）、DuplicateOrUnreadableName（规则名称不唯一或无法核对）、EdgeTraversal（附带边缘穿越设置）。
如果显示 Candidate，表示已读取的规则字段符合基础筛选；实际修复还需验证当前后台、网卡配置、Windows 授权和加密备份，不能据此认定已修复。
同时把电脑端“一键检查并修复”按钮下方的完整结果文字发来，以区分主动跳过、策略限制和执行错误。
发现阻止规则后，仍需判断它是否适用于当前 Wi-Fi/热点；不要仅因报告中出现 Block 就关闭整个防火墙。
程序路径和规则名称仅用于电脑本地比对，不写入报告。无法读取时会注明 unavailable，不代表已关闭防火墙。
规则数量不能证明连接一定放行，仍可能受规则地址范围、网络接口、服务、组织策略或其他安全软件影响。
报告不包含照片、配对码、密钥、用户名、电脑名、MAC地址、Wi-Fi名称或个人文件路径，也不会自动上传。
无需卸载 App 或重新安装。不要求管理员权限，不修改防火墙、VPN、路由或网络设置。

启动修复版：
启动文件已改为 ASCII 文本和 Windows CRLF 换行，兼容不同系统的中文代码页。
成功、缺少文件或脚本报错时，窗口都会保留；按任意键才关闭。
如果提示 Collect-ConnectionInfo.ps1 is missing，请完整解压，不要只复制 CMD。

说明：
“网卡未打开/没有正在使用 VPN”不等于系统里没有保留虚拟网卡。
电脑本机端口测试通过，不代表手机一定能访问，仍需结合手机 IP 和路由器隔离设置判断。
仅连接 USB 充电/文件传输不会自动建立本工具需要的局域网连接。
